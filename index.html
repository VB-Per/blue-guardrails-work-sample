The customer asked about A-77. The agent looked up A-78.

The lookup failed. The agent still told the customer their order was on its way. This synthetic trace shows how three checks can explain what went wrong.

The recorded exchange

Customer
“Where is my order A-77? Please include tracking.”
Tool call
get_order(order_id="A-78", include="tracking")
Tool response
OrderNotFoundError: no order A-78
Agent’s reply
“Your order A-77 is on its way. You can follow it with the tracking link in your account.”

What the checks found

  1. Invalid option. The tool accepts summary, shipping or items in the include field. The agent supplied tracking.
  2. Invented order ID. The user supplied A-77. No earlier customer message, instruction or tool result supplied A-78.
  3. Success after a failure. The lookup returned an error. The agent gave a shipping update without a successful retry.

Run the checks

Download the Python example and extract it. In the folder containing run.py, run the following command with Python 3.11 to 3.13. The example uses the standard library.

python3 run.py -v

The bundle includes four hand-written traces. The expected result is seven flags across three traces, with the clean trace passing each check. These fixtures demonstrate the rules. Measuring accuracy on a real agent requires separately labelled examples.
